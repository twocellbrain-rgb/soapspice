# BUILD A COMPLETE SOAP-MAKING EDUCATION, CALCULATOR, RECIPE & AFFILIATE PLATFORM

## 1. PROJECT OBJECTIVE

Build a professional, modern, mobile-responsive web application focused on soap making.

The website should combine:

1. Soap-making calculators
2. Ingredient database
3. Soap recipes
4. Step-by-step tutorials
5. Educational articles
6. Soap-making glossary
7. Troubleshooting guides
8. Safety information
9. Affiliate product recommendations
10. User accounts
11. Saved recipes and calculations
12. Search
13. SEO-friendly content architecture
14. Full administrator dashboard
15. Original/licensed visual content
16. Future compatibility with Amazon Product Advertising API
17. Architecture suitable for eventual deployment on Hostinger

The website should be inspired by the breadth and usability of established soap-making educational websites, but DO NOT copy another site's branding, layout, text, images, recipes, code, or proprietary content.

Create an original brand identity and original user experience.

---

# 2. DEVELOPMENT PRINCIPLES

Build this as a real production application rather than a simple demonstration.

Prioritize:

* Accuracy
* Maintainability
* Security
* Mobile responsiveness
* Fast loading
* SEO
* Accessibility
* Modular architecture
* Database-driven content
* Expandability
* Clear separation between frontend, backend, database, calculator engine, content system and affiliate system

Do not hard-code ingredients, recipes or affiliate products into frontend components.

Everything that may change should be database-driven and manageable through the admin dashboard.

---

# 3. IMPORTANT CONTENT POLICY

Do NOT scrape websites or copy/rewrite copyrighted articles simply to make them appear original.

The content system should support legitimate research and creation of genuinely original educational material.

Articles should be created from independently researched information and, where appropriate, multiple reliable sources.

Allow administrators to record:

* Source title
* Source URL
* Author
* Publisher
* Publication date
* Notes
* Attribution requirements

Do not automatically copy source text.

The system should support human review before publication.

Do not automatically publish AI-generated articles without administrator approval.

---

# 4. TECHNOLOGY ARCHITECTURE

Choose a modern, maintainable stack that works well in Replit and can be deployed to a conventional hosting environment.

Prefer:

Frontend:

* React
* TypeScript
* Modern CSS/Tailwind or equivalent

Backend:

* Node.js
* TypeScript
* REST API or clean server architecture

Database:

* PostgreSQL

Authentication:

* Secure session-based or token-based authentication

ORM:

* Use a reliable ORM such as Prisma or Drizzle.

* Database credentials
* Authentication secrets
* API keys
* Affiliate configuration
* Future Amazon API credentials

NEVER expose secrets in frontend code.

Structure the application so hosting can later be migrated from Replit to Hostinger with minimal architectural changes.

# 11. CALCULATOR VALIDATION

Implement strong validation.

Examples:

* Oil percentages must total 100%
* No negative quantities
* Ingredient must have required SAP data before being used
* Warn if unusual superfat values are entered
* Warn if formulation parameters fall outside configured ranges
* Prevent calculation when required data is missing
* Clearly identify assumptions
* Display units
* Allow recalculation when ingredients change

Include an expandable "Calculation Details" section.

Show how the result was calculated without exposing unnecessary implementation code.
